# GoDoc 编写与检查

## 工作入口

先按根目录 [AGENTS.md](../../../AGENTS.md) 的阅读顺序了解仓库。涉及包职责、依赖方向或装配边界时，对照 [AGENTS.md](../../../AGENTS.md) 与对应工程文档。

详细规范与示例按主题保存在 `references/`。先读取通用原则与排版规则，再按目标选择相关主题；交付前读取验证规范。

## 执行步骤

### 1. 确定范围

- 根据用户指定的文件、包或 diff 确定目标，定位所属 `go.mod` 与包声明。
- 用户要求检查或审查时，输出发现、代码位置与修改建议；用户要求编写或修订时，修改目标注释、`doc.go` 与必要的调用示例。
- 查看工作区已有改动，将本次编辑限定在用户授权范围内。

### 2. 核实行为

阅读目标声明、实现、调用方与相关测试，按选定的参考规范核实行为。每项行为说明都应有实现或测试依据。

发现文档与实现不一致时，说明差异；涉及 API 或运行行为调整的决策交给用户确认。

### 3. 编写或检查

按目标主题执行检查和修订，详细格式、边界与示例以对应参考文件为准。源码分区注释是可选的，不因缺少分区注释而补加。规范需要调整时，更新所属主题文件并同步受影响的阅读入口；文档维护遵循 [文档导航](../../../docs/README.md)。

### 4. 验证与交付

执行“验证与交付”参考文件中适用于本次改动的检查。复查实际 diff，确认声明、接口和运行逻辑符合本次授权范围，再汇报修改位置、检查结果与验证限制。
