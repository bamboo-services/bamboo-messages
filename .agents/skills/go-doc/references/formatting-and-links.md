# 排版与文档链接

## 小节标题

使用 Go 1.19+ 支持的单个 `#` 标题，标题前后各保留一个空注释行：

```go
// Package key 提供通用强类型键与转换方法。
//
// # 值解析
//
// [Key.Int] 与 [Key.Duration] 将键内容解析为对应类型，失败时返回错误。
//
// # 编解码
//
// [Key.MarshalText] 编码键值，[Key.UnmarshalText] 校验并写回解码结果。
package key
```

## 源码职责分区注释

分区注释是可选的源码导航手段，不作要求。Go Doc Comments、Effective Go、Go Code Review Comments 与 Google Go Style 都没有这种写法，标准库也基本不用；优先通过按职责拆分文件、保持声明顺序与空行来组织源码。

文件较长、职责组之间难以通过文件拆分区分时，可以使用分区注释：

- 分区粒度以职责组为单位，覆盖一组相关类型、常量、变量或函数。
- 使用三行 `//` 注释，上下两行采用等长的 `=` 分隔线，中间一行写简洁的中文职责标题；目标文件已有分区注释时沿用其风格。
- 标题说明稳定的能力或行为边界，保留必要的类型名与协议名，例如“Code 文本与 JSON 转换”“Code 数据库驱动支持”。
- 分区注释放在声明组之前，前后各保留一个源码空行，不紧贴声明，以免被当作符号的文档注释。
- 包级或符号 GoDoc 内的章节使用上文的 `// # 标题` 格式，不使用分隔线。

```go
// ============================================================================
// Code 文本与 JSON 转换
// ============================================================================
```

## 列表与换行

- 无序列表使用 `//   - 标识：说明`，续行与列表正文对齐。
- 长行按自然语义换行，建议保持适中的 70～80 字符行宽；行宽没有硬性要求，同一文件内保持一致。
- 段落内的中文只在空格处或中文标点之后断行，不在两个汉字之间断行。`go doc` 使用的 `go/doc/comment` 文本输出把段落内的换行连成一个空格：`按「依赖` 换行接 `先于使用者」` 输出为 `按「依赖 先于使用者」`，在词中间多出空格；在标点之后断行时，输出为 `释放， 使用者` 这样的标点后空格。
- 段落之间保留独立的空注释行 `//`；格式以 `gofmt` 输出为准。

```go
// 转换约定：
//
//   - 编码：值接收器输出文本、JSON 或 SQL 驱动值；
//   - 解码：指针接收器在校验成功后写回既有键值，
//     校验失败时返回错误并保留原值。
```

代码块的缩进与上下文见 [调用示例](./examples.md)。

## 本包符号链接

使用 Go 1.19+ 的 doc links 语法引用实际导出符号。例如在 `key` 包中引用 `[Key]`、`[Key.Int]`、`[Key.UnmarshalText]`。引用字段时核对类型与字段名称，例如某包的 `[Options.Writer]`。

## 跨包符号链接

包名前缀采用可解析的包名或导入别名，例如 `[netip.Addr]`、`[slog.Handler]`。需要消除歧义时，使用完整导入路径，例如 `[example.com/sdk/key.Key]`。

逐项核对引用符号是否存在、是否导出及所在包。使用标准库 `go/doc/comment` 渲染器或文档预览工具检查链接目标，源码编辑保持包的依赖边界。
